### Key Discoveries
- **Codex SessionStart stdout is invisible**: hook runs, output drops on
  the floor — only stderr surfaces. Combined with Codex's structural lack
  of SessionEnd/PreCompact/PostCompact/TaskCreated hooks, most of rpm's
  session-context discipline is absent in Codex. 0/63 Codex sessions show
  the rpm banner in conversation.
- **`context-monitor.sh` race condition**: non-atomic read-modify-write on
  the counter file. **543+ stderr crashes across 8 volta sessions**, peak
  198 crashes in one session (`c06be4a7-...jsonl:1690`).
- **`/backlog` bypassed at >99%**: direct-edit-to-skill ratio is 522:3 in
  Claude across all sampled projects, 103:0 in Codex. The skill's
  description doesn't claim natural verbs ("backlog X", "add to backlog").
- **`/session-end` is invoked MORE in Codex** (~30%) **than in Claude**
  (~2%). Intuition inverted: Codex sessions are smaller and more
  transactional; Claude sessions persist across days and die without
  ceremony.
- **volta marker `task: (unassigned)` stuck for 27+ days** surviving
  multiple CC and Codex sessions — neither runtime backfills it when the
  session dies without /session-end. 215 propagated occurrences in
  Codex; 240 instances of `(unassigned)` in CC SessionStart previews.
- **Hardcoded `claude-plugins-official/rpm/unknown/` placeholder** ships
  in skill bodies. Assistants bash a nonexistent path before
  find-recovering. `unknown` looks like an unrendered template segment.
- **scan.sh emits `version=unknown` in Codex** (47 occurrences) because
  `${CLAUDE_PLUGIN_ROOT}` is unset and scan.sh has no Codex-side resolver.
- **SessionStart hook output truncation**: 152KB peak in volta. Combined
  with Codex's stdout-invisible reality, this is CC-only effective issue.
- **Auditor confidently surfaces findings against stale docs without
  cross-checking live code**: one reddit-reports auditor run produced 13
  wrong findings about a decommissioned VPS.

### Key Discoveries
- **Loop-mode "no actionable" needs an escape valve.** When the top
  topmost TODO carries explicit deferral text ("DECISION NEEDED",
  "Defer until observed", "Hasn't been observed in practice"),
  treating it as actionable would mean autonomously guessing the
  user's design call. The right move is to flip to BLOCKED so the
  loop walks past it instead of idling on the same entry until
  `loop-exhausted`. This is now the practical pattern when the
  /next orchestrator hits a soft-deferred top item — earlier
  fixes (`WATCH` keyword) standardize this on the next cycle.
- **F4's pre-completed-task guard locks in retroactively.** The new
  `is-pre-completed.sh` now exits 0 for every detail file touched
  this session — future `/next` ticks will skip the wasted dispatch
  if any DONE flip is ever missed in tasks.org.
- **Worker `agent_id` drift.** Workers default to
  `worker-unknown` because runtime doesn't pass an agent ID to the
  subagent prompt. The orchestrator logs the dispatch ID; the worker
  logs `worker-unknown`. `review-ready.sh` joins by target+agent_id,
  so reviewed entries can still surface as "needs-review" until the
  agent-id pairing is fixed. Worked around inline by logging
  review-result entries; the underlying script bug is a follow-up.
