## Key Discoveries
- W&D pattern (parallel tool calls inside one agent) cuts tokens ~57%
  on comparison-shaped tasks vs. multi-subagent, and surfaces
  cross-entity patterns that are architecturally invisible to
  multi-subagent designs (each sub-agent is sandboxed to one entity).
- urlhealth (arxiv:2604.03173) is a deterministic, non-LLM check that
  cuts non-resolving citation URLs by 6–79× to <1% — pure HTTP HEAD,
  no model needed.
- 3–13% of citation URLs in production DR agents are fully fabricated
  (no Wayback record). 5–18% non-resolving overall. DR agents
  hallucinate URLs at higher rates than simpler search-augmented LLMs
  because they generate more citations.
- Indirect prompt injection in fetched URL content is in the wild —
  Comet AI summarizer leaked an OTP after reading hidden Reddit-post
  instructions (Apr 2026). Curl-fetched HTML must be wrapped as
  data-only.
- Verbalized confidence from RLHF models is poorly calibrated:
  GPT-4 AUROC on its own stated confidence ≈ 62.7%; ECE > 0.377
  across GPT-3/3.5/Vicuna (arXiv:2306.13063). Bare H/M/L tags are
  barely better than random — must be source-grounded to be useful.
- None of the major open-source DR agents (LangChain ODR, MiroThinker,
  GPT-Researcher) implement runtime HTTP URL-resolution checks as of
  2026 — universal gap across the ecosystem.

## What Didn't Work
- First curl batch in the original deep-research run leaked 11 of 12
  fetched HTML files to project root: `cd $dir && curl1 & curl2 & ...`
  parses as `(cd && curl1) &` followed by `curl2 &` etc., so only the
  first curl ran inside the cd-affected subshell. Fix: cd in a
  separate command, or wrap the whole batch in `(cd $dir && (curl1 &
  curl2 & ... wait))`.
- Citation-audit agent reported AgentIR conventional-baseline as 52%
  but the fetched abstract said 50%. Resolved by hedging in the
  report ("~50%; audit reported 52%; discrepancy unresolved, doesn't
  change qualitative claim") rather than picking one.
