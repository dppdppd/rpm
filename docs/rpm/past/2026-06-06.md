# 2026-06-06

## Accomplished
- Added a `/next` count/scope argument and made repeated runs cheaper
  (released **v2.24.0**, CC + opencode + codex + tag):
  - `/next N | blocked | all | <group>` now runs a **bounded internal
    sequence** in one turn — foreground, strictly one worker at a time (no
    fan-out; the 2026-05-04 one-worker audit still holds). `blocked` stops
    when a task needs the user, `all` skips those and drains the rest,
    `<group>` restricts to one `* Parent`.
  - A sequence runs the full preflight only at the **start and end**;
    in-between cycles just review the worker that finished. This removes the
    per-tick drift-scan + memory/docs-check overhead that dominated
    `/loop /next`.
  - New `plugin/skills/next/scripts/preflight-due.sh` gives the external
    `/loop /next` path the same saving (full|lite by a 10-min freshness
    window + an input-change check). New `phases=review-only` mode on the
    preflight agent keeps a finished worker's diff out of the orchestrator
    on lite ticks.
  - New `preflight-due.bats` (6 tests); suite 206 → 212; shellcheck clean.

## Key Discoveries
- The codex translator (`scripts/translate-skill-codex.py`) rewrites the
  shared SKILL body with **exact-string matches** and a **hardcoded codex
  `next` description**. Restructuring a synced skill silently breaks those
  rewrites — my edits left four untranslated `/loop /next` and a stale
  description. `codex-port.bats` is the safety net that caught it. I added
  token-level catch-alls to the translator so future restructuring of the
  shared body keeps translating to the Codex idiom.

## What Didn't Work
- The first codex sync after the skill rewrite failed one codex-port test
  (untranslated `/loop /next`). Fixed by hardening the translator rather
  than hand-patching the generated codex file.
